REPACK

REPACK — rewrite a table to reclaim disk space

概要

REPACK [ ( option [, ...] ) ] [ table_and_columns [ USING INDEX [ index_name ] ] ]
REPACK [ ( option [, ...] ) ] USING INDEX

where option can be one of:

    VERBOSE [ boolean ]
    ANALYZE [ boolean ]
    CONCURRENTLY [ boolean ]

and table_and_columns is:

    table_name [ ( column_name [, ...] ) ]

説明

《機械翻訳》REPACKは、無効なタプルによって占有されたストレージを回収します。 VACUUMとは異なり、table_nameで指定された名前の内容全体を、余分なディスクファイルのない新しいスペースに書き換えることによって行われます（fillfactorストレージパラメータによって保証されたスペースを除き、未使用のスペースをオペレーティングシステムに戻すことができます）。

《機械翻訳》table_nameがない場合、REPACKは、現在データベースにMAINTAIN権限があるすべてのテーブルおよびマテリアライズドビューを処理します。 REPACKのこのフォームは、トランザクションブロック内では実行できません。 また、CONCURRENTLYオプションが使用されている場合、このフォームは許可されません。

《機械翻訳》USING INDEX句を指定すると、インデックスからの情報に基づいて、行が物理的に並べ替えられます。 下記のNotes on Clusteringを参照してください。

《機械翻訳》テーブルを再パックする場合、ACCESS EXCLUSIVEオプションが指定されていなければ、そのテーブルに対してCONCURRENTLYロックが獲得されます。 このオプションの影響についてはNotes on Concurrent Operationを参照してください。

パラメータ

table_name

《機械翻訳》テーブルの名前です（スキーマ修飾名も可）。

column_name

《機械翻訳》特定のカラムからANALYZEまでの名前。 デフォルトはすべての列です。 カラムリストが特定の場合は、ANALYZEも指定する必要があります。

index_name

《機械翻訳》インデックスの名前です。

CONCURRENTLY

《機械翻訳》再パック中に、他のトランザクションがテーブルを使用できるようにします。 詳細は、Notes on Concurrent Operationを参照してください。

VERBOSE

《機械翻訳》各レポートがINFOテーブルで再梱包されるときに、進行レベルを印刷します。

ANALYZE
ANALYSE

《機械翻訳》再梱包後にテーブルにANALYZEを適用します。 これは現在、単一の（パーティション化されていない）テーブルが指定されている場合にのみサポートされています。 このオプションは、トランザクションブロック内では使用できません。 また、関数、プロシージャ、またはDOブロックからは使用できません。

boolean

《機械翻訳》選択したオプションをオンにするか、オフにするかを指定します。 TRUE、ON、または1と記述するとオプションが有効になり、FALSE、OFF、または0と記述すると無効になります。 ブールの値を省略することもでき、その場合はケースTRUEが想定されます。

注釈

《機械翻訳》テーブルを再梱包するには、テーブルにMAINTAIN権限が必要です。

《機械翻訳》REPACKは、主に膨張を除去することを目的としており、USING INDEXとともにテーブルのクラスタまで、オーダーではパフォーマンスの改善までです。 テーブルのrelfrozenxidとrelminmxidも進みますが、トランザクションIDやマルチトランザクションIDの周回を防ぐのには適していません。 これは、テーブル全体とそのインデックスのすべてを書き換えるため、VACUUMよりもはるかに時間がかかり、特にCONCURRENTLYビジーテーブルで使用する場合は失敗する可能性があります。 VACUUM代わりに推奨します（24.1.5を参照）。 テーブルがクローズから周回に移動する場合、VACUUMはインデックスバキューム処理を自動的にスキップします（vacuum_failsafe_ageを参照）。 INDEX_CLEANUP OFFオプションを使用すると、同じことをより早く行うことができます。

《機械翻訳》REPACK無効なプロセスが存在するテーブルのインデックスを拒否します。 このようなインデックスは、事前にユーザによって削除または再インデックスされる必要があります。

《機械翻訳》REPACKの実行中は、search_pathが一時的にpg_catalog, pg_tempに変更されます。

《機械翻訳》運行している各バックエンドREPACKビュー内でのレポートの進行状況。 詳細は27.4.5を参照。 pg_stat_progress_repack

《機械翻訳》パーティション化されたテーブルを再パックすると、各パーティションが再パックされます。 インデックスが指定されている場合は、そのパーティションのパーティションを使用して各インデックスが再パックされます。 REPACKパーティション化されたテーブルでは、トランザクションブロック内で実行できません。

《機械翻訳》クラスタリングに関する注意。

《機械翻訳》USING INDEX句が指定されている場合、そのテーブルの行は、指定された順序付けによって示されるインデックスに従って物理的に再配置されます。 これはクラスタリングと呼ばれます。 これはパフォーマンスに影響を与える可能性があります。 テーブル内で単一の行をランダムにアクセスしている場合、テーブル内のデータの実際のオーダーは重要ではありません。 ただし、一部のデータを他のよりも多くアクセスする傾向があり、それらをグループ化するインデックスがある場合は、クラスタリングを使用することでメリットが得られます。 テーブルからインデックス付けされた値のレンジを要求している場合、またはマルチプルマッチング行を持つ単一のインデックス付けされた値を要求している場合、クラスタリングはヘルプになります。 これは、インデックスが一致する最初の行のテーブルページを識別すると、マッチを持つ他のすべての行はおそらくすでに同じテーブルページにあるため、ディスクアクセスを節約し、問い合わせを高速化します。

《機械翻訳》Bツリー索引の場合、クラスタリングで使用される順序付けは、そのインデックスのリニアソートオーダーです。 その他のクラスタリング可能インデックスアクセスメソッドでは、別の順序付けストラテジが使用される場合があります。 このは、SQLソートオーダーに対応しているとはかぎりません。 コマンドでインデックス名前が指定されている場合、そのインデックスが使用され、テーブルのクラスタリングインデックスとして記録されます。 CLUSTERコマンドに指定されたインデックスについても同様です。 インデックス名前が指定されていない場合は、クラスタリング対象として構成されているインデックスが使用されます。 構成されていない場合は、エラーがスローされます。 インデックスを手動で設定するには、ALTER TABLE ... CLUSTER ONを使用し、リセットをALTER TABLE ... SET WITHOUT CLUSTER.

《機械翻訳》クラスタ化は1回限りのオペレーションです。 テーブルがその後更新された場合、その変更はクラスタ化されません。 つまり、クラスタ化されたオーダーに従って、新規または更新された行を格納しようとすることはありません。 (必要であれば、コマンドを再度発行することで定期的に再クラスタ化できます。 また、テーブルを設定するとfillfactorストレージパラメータをより小さい100%に設定すると、更新時にクラスタ順序付けを保護するのに役立ちます。 これは、十分なスペースが利用可能な場合、更新された行は同じページに保持されるためです。

《機械翻訳》B-ツリーインデックスでクラスタリングしている場合、REPACKは、指定したテーブルのインデックススキャン、またはインデックスの後にシーケンシャルスキャンを使用して並べ替えを書き換えることができます。 プランナコストパラメータおよび使用可能なメソッド情報に基づいて、より高速な統計の選択が試行されます。 B-ツリー以外のアクセス方式のインデックスでクラスタリングしている場合、REPACKは常にインデックススキャンを使用します。

《機械翻訳》プランナはテーブルの統計処理に関する順序付けを記録しますので、ANALYZEオプションを指定するか、新しくパックし直したテーブルに対してANALYZEを実行することを推奨します。 さもないと、そのプランナは、問い合わせ計画の不適切な選択をmakeする可能性があります。

《機械翻訳》REPACK USING INDEXでテーブル名前が指定されていない場合は、クラスタ化インデックスが定義されていて、コール側ユーザが権限を持っているすべての表が処理されます。

《機械翻訳》リソースに関するメモ。

《機械翻訳》REPACKでは、テーブルの一時的コピーとそのすべてのインデックスが作成されます。 このため、フリーディスクスペースは少なくとも等しいテーブルサイズの総和とインデックスのサイズが必要です。

《機械翻訳》USING INDEX句が指定され、プランナがそれを実装するシーケンシャルスキャンとソートを選択した場合は、上記に加えて、テーブルのサイズまでの一時的ソートファイルが必要です。 このメソッドは通常、インデックススキャンよりも高速ですが、ディスクスペースの条件が許容できない場合は、enable_sortを一時的にoff;に設定するか、テーブルの順序変更が必要ない場合はUSING INDEXを省略することで、この選択を無効にできます。

《機械翻訳》トランザクションIDの周回（24.1.5を参照）において、REPACKは単一の長時間実行されるトランザクションとみなされ、これによりVACUUM他のテーブルの不要行の整理を防ぐことができます。 REPACK非常にラージなテーブルを再パックする場合、他のテーブルの過剰な膨張を防ぐために実行中のプロセスに対してモニタpg_stat_activity.backend_xidを使用することをお勧めします。

《機械翻訳》maintenance_work_memを適切なラージの値に設定することをお勧めします（ただし、REPACKオペレーションの前のリパックに使用できるRAMの量を超えないようにしてください）。

《機械翻訳》同時オペレーションに関する注意。

警告

《機械翻訳》REPACKとCONCURRENTLYオプションはMVCC-セーフではありません。 トランザクションの再パッキングがコミットされた後、同時トランザクションがテーブルの再パッキングを開始したsnapshotを使用している場合、その前は同時トランザクションに対して空であるように見えます。 詳細は、13.6を参照してください。

《機械翻訳》REPACKは、テーブル（無効タプルは無視）の内容を、指定したファイルでソートして新規インデックスにコピーし、さらにファイルごとに新規インデックスを作成します。 次に、テーブルおよびすべてのインデックスについて、古いファイルと新規ファイルを入れ替え、古いファイルを削除します。 CONCURRENTLYオプションを使用しない場合、ACCESS EXCLUSIVEロックは最初に取得され、オペレーションからmakeまで保持され、処理中に古いファイルが変更されないようにします。 そうしないと、スワップによって同時に行われた変更が失われます。

《機械翻訳》対照的に、CONCURRENTLYオプションが指定された場合、オペレーションのバルクはSHARE UPDATE EXCLUSIVEロックとともに実行され、ACCESS EXCLUSIVEロックはテーブルおよびインデックスファイルをスワップする最終フェーズでのみ取得されます。 新しいテーブルおよびインデックスファイルの作成中に発生したデータの変更は、ロジカルデコーディング（第47章を参照）を使用して取得され、前に適用されますACCESS EXCLUSIVEロックが要求されます。 ロックが取得されると、取得された残りの同時データの変更に対する最終パスが実行され、ファイルがスワップされます。 したがって、ロックは通常、ロックが待機されている間に蓄積された変更の量に応じて、短時間保持されます。

《機械翻訳》これらの同時変更の処理には、同時に更新または削除される各メモリに対して固定された少量のタプルが必要であり、maintenance_work_memによって制限されません。 REPACKの実行中に約104,000,000行を超える行が同時に更新または削除されると、コマンドに障害が発生します。 さらに、すべての同時変更の完全なタプルデータ（UPDATEによって変更されないTOAST列を除く）は、ディスクに個別に格納されます。

《機械翻訳》REPACK (CONCURRENTLY)再パック中に他のトランザクションがDDL上でテーブルコマンドを実行すると、が完了しない可能性があります。

《機械翻訳》REPACK (CONCURRENTLY) USING INDEX再パックの開始後にトライに挿入された行は、オーダーからテーブルに移動されません。

《機械翻訳》CONCURRENTLYオプションは、次の場合には使用できません。

  • 《機械翻訳》リレーションがテーブルではありません（マテリアライズドビューなど）。

  • 《機械翻訳》テーブルはUNLOGGEDです。

  • 《機械翻訳》テーブルは仕切られている。

  • 《機械翻訳》このテーブルには、主キーやインデックスを拠点とするレプリカアイデンティティがありません。

  • 《機械翻訳》テーブルは、システムカタログまたはテーブルTOASTです。

  • 《機械翻訳》テーブルのアクセス方法はheap.NET以外ではありません。

  • 《機械翻訳》このテーブルは、user_catalog_tableカタログテーブルを使用してストレージパラメータとして宣言されています。

  • 《機械翻訳》REPACKトランザクションブロック内で実行されます。

  • 《機械翻訳》max_repack_replication_slots設定パラメータでは、追加のレプリケーションスロットを作成できません。

例

《機械翻訳》テーブルemployeesを再梱包します。 

REPACK employees;

《機械翻訳》テーブルemployeesを、インデックスemployees_indに基づいて再梱包します（インデックスが指定されているため、これは効果的にクラスタリングされます）。 

REPACK employees USING INDEX employees_ind;

《機械翻訳》テーブルemployeesを、前に使用されたのと同じインデックスに従って、同時実行モードで再梱包します。 

REPACK (CONCURRENTLY) employees USING INDEX;

《機械翻訳》テーブルcasesを物理的順序付けで再梱包し、再梱包が完了すると、特定の列でANALYZEを実行し、情報メッセージを表示します。 

REPACK (ANALYZE, VERBOSE) cases (district, case_nr);

《機械翻訳》MAINTAIN権限を持つデータベース内のすべてのテーブルを再梱包します。 

REPACK;

《機械翻訳》MAINTAIN権限を持ち、以前にクラスタリングインデックスが構成されたすべてのテーブルを再梱包し、情報メッセージを表示します。 

REPACK (VERBOSE) USING INDEX;

互換性

《機械翻訳》ステートメント基準ではREPACK SQLはない。
