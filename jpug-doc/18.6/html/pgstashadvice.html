F.33. pg_stash_advice — store and automatically apply plan advice #

《機械翻訳》pg_stash_adviceextensionを使用すると、プランアドバイス文字列を動的共有メモリに隠して、自動的に適用できます。 advice stashは問い合わせ識別子からプランアドバイス文字列までのマッピングです。 セッションがプラン問い合わせに要求され、その問い合わせIDが関連するアドバイス隠しに表示されるたびに、プランアドバイス文字列がガイドplanning. ノートに自動的に適用され、アドバイス隠しが動的に割り当てられた共有メモリに格納されます。 これは、プランアドバイスの量を決定する際に、メモリの消費に注意することが重要であることを意味します。 オプションで、アドバイス隠しとその内容を自動的にディスクに保持し、ディスクから再ロードすることができます。 下記のpg_stash_advice.persistを参照してください。

《機械翻訳》オーダーでこのモジュールを使用するには、実行CREATE EXTENSION pg_stash_advice少なくとも1つのデータベースで、アクセスからSQLへの機能を使用してアドバイスの隠し場所を管理する必要があります。 また、このモジュールでアドバイスを自動的に適用するすべてのセッションでpg_stash_adviceモジュールをロードする必要があります。 通常はベストで、shared_preload_librariesにpg_stash_adviceを追加し、サーバを再起動します。

《機械翻訳》前述の基準を満たした後は、pg_create_advice_stash後述のアドバイスを使用して関数の隠し場所を作成し、pg_set_stashed_adviceプランを使用して、特定の隠し場所の特定の問い合わせIDに対して関数アドバイスを設定できます。 その後は、pg_stash_advice.stash_name選択したアドバイスの隠し場所名前にポイントするように構成するだけで済みます。 一部のユースケースでは、システム全体にこの値を設定するよりも、データベースまたは特定のロールのみに適用される値を構成するためにALTER DATABASE ... SETまたはALTER ROLE ... SETを使用することをお薦めします。 同様に、SETを使用して特定のセッションに隠し場所名前を設定する方がよい場合もあります。

《機械翻訳》pg_stash_adviceは問い合わせ識別子に基づいて動作するため、問い合わせをコントロールにしたい問い合わせごとに、プラン識別子を決定する必要があります。 また、各問い合わせに対して保存したいアドバイス文字列を決定する必要もあります。 これを行う1つの方法は、EXPLAIN:VERBOSEオプションは問い合わせIDを表示し、PLAN_ADVICEオプションはプランアドバイスを表示します。 問い合わせ識別子はpg_stat_statementsや27.2.3などのツールを使用して取得することもできますが、これらのツールはプランアドバイス文字列を提供しません。 ノート問い合わせ識別子を計算するには、このcompute_query_idが有効になっている必要があります。 autoに設定されている場合、ロード時にpg_stash_adviceは自動的に有効になります。

《機械翻訳》隠されたアドバイスは、問い合わせが計画されている場合にのみ適用されます。 隠されたエントリを追加、置換または削除したり、pg_stash_advice.stash_nameを変更しても、すでにキャッシュされている計画には影響しません。 F.30.7を参照してください。

《機械翻訳》一般的に、プランナの基礎となるディストリビューションが変更されたときにデータが問い合わせ計画を変更できるのは、機能であってバグではありません。 さらに、プランアドバイスを適用すると、問い合わせプランへの変更を伴わない場合でも、顕著なパフォーマンスコストが発生する可能性があります。 したがって、この機能は、必要なときに必要なエクステントにのみ使用するのが良いアイディアです。 プランアドバイス文字列はダウンをトリムして、制御が必要なプランの側面のみを言及し、プランナエラーのかなりのリスクがあると考えられる問い合わせにのみ使用できます。

《機械翻訳》ノートpg_stash_advice現在、高度なセキュリティモデルがありません。 スーパーユーザまたはユーザが付与したスーパーユーザEXECUTE関連する機能に関するパーミッションのみが、アドバイスの隠し場所を作成したり、その内容を変更したりできますが、ユーザはpg_stash_advice.stash_nameそのセッションに対して設定することができ、これにより、その名前とともに隠されているアドバイスの内容が明らかになる可能性があります。 ユーザは、隠されたアドバイス文字列内の情報埋め込みが、特権のないユーザには可視になる可能性があると想定する必要があります。

F.33.1. Functions #

pg_create_advice_stash(stash_name text) returns void

《機械翻訳》指定されたアドバイスで、新しい空の名前の隠し場所を作成します。

pg_drop_advice_stash(stash_name text) returns void

《機械翻訳》記名的アドバイスのstashとそのすべてのエントリを削除します。

pg_set_stashed_advice(stash_name text, query_id bigint, advice_string text) returns void

《機械翻訳》指定したアドバイス文字列に関連付けられた記名的アドバイスのスタッシュに問い合わせ識別子を格納します。 その問い合わせ識別子のエントリがすでにスタッシュに存在する場合は、置き換えられます。 advice_stringがNULLの場合は、その問い合わせ識別子の既存のエントリが削除されます。

pg_get_advice_stashes() returns setof (stash_name text, num_entries bigint)

《機械翻訳》行の各隠し場所に対して1つのアドバイスを返し、隠し場所の名前とその包含のエントリ数を表示します。

pg_get_advice_stash_contents(stash_name text) returns setof (stash_name text, query_id bigint, advice_string text)

《機械翻訳》行アドバイススタッシュ内のエントリごとに1つの記名的を戻します。 stash_nameがNULLの場合は、すべてのスタッシュからエントリが戻されます。

pg_start_stash_advice_worker() returns void

《機械翻訳》バックグラウンドワーカーを起動し、アドバイスのstashコンテンツを自動的にディスクに永続化できるようにします。 このモジュールがpg_stash_advice.persist = trueでスタートアップ時間にshared_preload_librariesに含まれている場合、ワーカーは自動的に起動されます。 手動で起動した場合、ワーカーはディスクから何もロードしませんが、データからディスクまでは存続します。 次のリスタートの後に、サーバからワーカーに自動的にスタートするように構成できます。 これにより、今追加したstashアドバイスが保持されます。

F.33.2. 設定パラメータ #

pg_stash_advice.persist (boolean)

《機械翻訳》アドバイスのstashおよびstashエントリをディスクに保持するかどうかを制御します。 これはデフォルトによるものです。 stashが保持されている場合は、ファイルに記名的pg_stash_advice.tsvが作成されます。 stashはバックグラウンドワーカープロセスを使用してロードおよび保存されます。 このパラメータはサーバスタートでのみ設定できます。 データディレクトリ

pg_stash_advice.persist_interval (integer)

《機械翻訳》書き込む必要がある変更をチェックする間隔pg_stash_advice.tsv秒を指定します。 ゼロに設定すると、サーバがダウンを閉鎖するときにのみ変更が書き込まれます。 デフォルト値は30です。 このパラメータは、postgresql.confファイルまたはサーバコマンドラインでのみ設定できます。 インターバル

pg_stash_advice.stash_name (string)

《機械翻訳》問い合わせの計画中に参照される名前の隠し場所のアドバイスを指定します。 デフォルト値は空の文字列で、このモジュールを無効にします。
