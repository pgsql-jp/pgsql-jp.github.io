pg_test_timing

pg_test_timing <refpurpose>measure timing overhead</refpurpose> — 時間計測のオーバーヘッドを測定する

概要

pg_test_timing [option...]

説明

<title>Description</title>

<application>pg_test_timing</application> is a tool to measure the timing overhead on your system and confirm that the system time never moves backwards. It reads supported clock sources over and over again as fast as it can for a specified length of time, and then prints statistics about the observed differences in successive clock readings, as well as which clock source will be used. 《マッチ度[51.288660]》《タグ不一致》pg_test_timingはシステム上の時間計測のオーバーヘッドを測定し、またシステム時計が逆向きに進まないことを確認するためのツールです。 時間のデータの収集に時間のかかるシステムでは、EXPLAIN ANALYZEの結果が不正確になることがあります。 《機械翻訳》pg_test_timingは、ツール上のタイミング・オーバーヘッドを測定し、システム時間が決して逆方向に移動しないことを確認するためのシステムです。 これは、サポートされているクロックソースを、指定された長さの時間で可能な限り高速に何度も繰り返し読み込み、次に、連続するクロック読み取りで観測された差に関する統計処理と、どのクロックソースが使用されるかを出力します。

Smaller (but not zero) differences are better, since they imply both more-precise clock hardware and less overhead to collect a clock reading. Systems that are slow to collect timing data can give less accurate <command>EXPLAIN ANALYZE</command> results. 《機械翻訳》（ゼロではなく）差が小さいほど優れています。 これは、クロックハードウェアの精度が高いことと、クロックの測定値を収集するためのオーバーヘッドが少ないことの両方を意味するためです。 タイミングデータの収集に時間がかかるシステムでは、精度が低くなる可能性がありますEXPLAIN ANALYZE結果。

This tool is also helpful to determine if the <varname>track_io_timing</varname> configuration parameter is likely to produce useful results, and whether the <acronym>TSC</acronym> clock source (see <xref linkend="guc-timing-clock-source"/>) is available and if it will be used by default. 《機械翻訳》このツールは、track_io_timing設定パラメータが有用な結果をもたらす可能性があるかどうか、TSCクロックソース（timing_clock_sourceを参照）が利用可能かどうか、およびそれがデフォルトによって使用されるかどうかを判断するのにも役立ちます。

オプション

<title>Options</title>

<application>pg_test_timing</application> accepts the following command-line options: pg_test_timingでは、以下のコマンドラインオプションを指定できます。

-c cutoff
--cutoff=cutoff

Specifies the cutoff percentage for the list of exact observed timing durations (that is, the changes in the system clock value from one reading to the next). The list will end once the running percentage total reaches or exceeds this value, except that the largest observed duration will always be printed. The default cutoff is 99.99. 《機械翻訳》正確な観測リスト期間（つまり、ある読み取り値から次の読み取り値へのタイミング値の変化）のシステムクロックのカットオフパーセンテージを指定します。 リストは、実行パーセンテージの合計がこの値に達するか超えると終了します。 ただし、観測された期間の最大値は常に印刷されます。 デフォルトカットオフは99.99です。

-d duration
--duration=duration

Specifies the test duration, in seconds. Longer durations give slightly better accuracy, and are more likely to discover problems with the system clock moving backwards. The default test duration is 3 seconds. テストの時間を秒単位で指定します。 時間を長くすると、少しだけ結果が正確になり、またシステム時計が逆方向に進む問題を検出できる可能性が高くなります。 デフォルトのテスト時間は3秒です。

-V
--version

Print the <application>pg_test_timing</application> version and exit. pg_test_timingのバージョンを表示して終了します。

-?
--help

Show help about <application>pg_test_timing</application> command line arguments, and exit. pg_test_timingのコマンドライン引数についてのヘルプを表示して終了します。

使用方法

<title>Usage</title>

結果の解釈

<title>Interpreting Results</title>

The first block of output has four columns, with rows showing a shifted-by-one log2(ns) histogram of timing durations (that is, the differences between successive clock readings). This is not the classic log2(n+1) histogram as it counts zeros separately and then switches to log2(ns) starting from value 1. 《機械翻訳》出力の最初のブロックには4つの列があり、ログ期間（つまり、連続するタイミング読み取り値間の差）のヒストグラム2(ns)を1つずつシフトして表示する行があります。 これは、ゼロを個別にカウントし、値1から始まるログ2(ns)に切り替わるため、従来の2(n+1)ヒストグラムではありません。 クロックログ

The columns are: 《機械翻訳》列は次のとおりです。

  • nanosecond value that is >= the durations in this bucket
  • percentage of durations in this bucket
  • running-sum percentage of durations in this and previous buckets
  • count of durations in this bucket

The second block of output goes into more detail, showing the exact timing differences observed. For brevity this list is cut off when the running-sum percentage exceeds the user-selectable cutoff value. However, the largest observed difference is always shown. 《機械翻訳》出力の2番目のブロックはより詳細で、観測された正確なタイミングの違いを示しています。 簡潔にするために、このリストは、現在のオフの割合が総和の選択可能なカットオフ値を超えたときにユーザがカットされます。 ただし、観測された差の最大値は常に表示されます。

On platforms that support the <acronym>TSC</acronym> clock source, additional output sections are shown for the <command>RDTSCP</command> instruction (used for general timing needs, such as <varname>track_io_timing</varname>) and the <command>RDTSC</command> instruction (used for <command>EXPLAIN ANALYZE</command>). At the end of the output, the <acronym>TSC</acronym> frequency, which may either be sourced from CPU information directly, or the alternate calibration mechanism are shown, as well as whether the <acronym>TSC</acronym> clock source will be used by default. 《機械翻訳》サポートTSCクロックソースのプラットフォームでは、RDTSCP命令track_io_timingやRDTSC EXPLAIN ANALYZEに使用される命令など、一般的なタイミングニーズに使用されるの追加の出力セクションが表示されます。 出力の最後に、TSC周波数が表示されます。 この周波数は、CPU情報から直接取得することも、代替の調整メカニズムから取得することもできます。 また、TSCクロックソースがデフォルトで使用されるかどうかも表示されます。

The example results below show system clock timing where 99.99% of loops took between 16 and 63 nanoseconds. In the second block, we can see that the typical loop time is 40 nanoseconds, and the readings appear to have full nanosecond precision. Following the system clock results, the <acronym>TSC</acronym> clock source results are shown, in the same fashion. The <command>RDTSCP</command> instruction shows most loops completing in 20&ndash;30 nanoseconds, while the <command>RDTSC</command> instruction is the fastest with an average loop time of 20 nanoseconds. In this example the <acronym>TSC</acronym> clock source will be used by default, but can be disabled by setting <varname>timing_clock_source</varname> to <literal>system</literal>. 《機械翻訳》次の例の結果は、システムクロックタイミングを示しており、ループの99.99%が16～63ナノ秒の間で行われています。 2番目のブロックでは、一般的なループ時間は40ナノ秒であり、測定値は完全なナノ秒精度を持っているように見えます。 システムクロックの結果に続いて、TSCクロックソースの結果が同じ方法で示されています。 RDTSCP命令は、ほとんどのループが20–30ナノ秒で完了することを示していますが、RDTSC命令は平均ループ時間20ナノ秒で最も高速です。 この例では、TSCクロックソースがデフォルトによって使用されますが、timing_clock_sourceをsystemに設定することで無効にできます。
