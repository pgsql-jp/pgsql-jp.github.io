WAIT

WAIT — wait for WAL to reach a target LSN

概要

WAIT FOR LSN 'lsn'
    [ WITH ( option [, ...] ) ]


<phrase>where <replaceable class="parameter">option</replaceable> can be:</phrase>

ここでoptionは以下の通りです。

    MODE 'mode'
    TIMEOUT 'timeout'
    NO_THROW

and mode can be:

    standby_replay | standby_write | standby_flush | primary_flush

説明

<title>Description</title>

Waits until the specified <parameter>lsn</parameter> is reached according to the specified <parameter>mode</parameter>, which determines whether to wait for WAL to be written, flushed, or replayed. If no <parameter>timeout</parameter> is specified or it is set to zero, this command waits indefinitely for the <parameter>lsn</parameter>. 《機械翻訳》指定されたlsnに達するまで待機します。 指定されたmodeは、WALの書き込み、フラッシュ、再生を待つかどうかを決定します。 timeoutが指定されていない場合、またはゼロに設定されている場合、このコマンドはlsnを無期限に待機します。

On timeout, an error is emitted unless <literal>NO_THROW</literal> is specified in the WITH clause. For standby modes (<literal>standby_replay</literal>, <literal>standby_write</literal>, <literal>standby_flush</literal>), an error is also emitted if the server is promoted before the <parameter>lsn</parameter> is reached. If <parameter>NO_THROW</parameter> is specified, the command reports these outcomes as a status string instead of raising an error. 《機械翻訳》タイムアウトでは、WITHエラーでNO_THROWが指定されていない限り、句が放出されます。 スタンバイモード(standby_replay,standby_write,standby_flushでは、サーバが前lsnに到達したときにもエラーが放出されます。 NO_THROWが指定されている場合、コマンドはこれらの結果をステータス文字列代わりがエラーを上げるものとして報告します。

The possible return values are <literal>success</literal>, <literal>timeout</literal>, and <literal>not in recovery</literal>. 《機械翻訳》使用可能な結果値はsuccess、timeout、およびnot in recoveryです。

パラメータ

<title>Parameters</title>
lsn

Specifies the target <acronym>LSN</acronym> to wait for. 《機械翻訳》待機するターゲットLSNを指定します。

WITH ( option [, ...] )

This clause specifies optional parameters for the wait operation. The following parameters are supported: 《機械翻訳》この句は、待機オプションパラメータのオペレーションを指定します。 次のパラメータがサポートされています。

MODE 'mode'

Specifies the type of LSN processing to wait for. If not specified, the default is <literal>standby_replay</literal>. The valid modes are: 《機械翻訳》待機するLSN処理のタイプを指定します。 指定されていない場合、デフォルトはstandby_replayです。 有効なモードは次のとおりです。

  • <literal>standby_replay</literal>: Wait for the LSN to be replayed (applied to the database) on a standby server. After successful completion, <function>pg_last_wal_replay_lsn()</function> will return a value greater than or equal to the target LSN. This mode can only be used during recovery. 《機械翻訳》standby_replay:データベースでLSNがリプレイされるpg_last_wal_replay_lsn()スタンバイサーバに適用されるのを待機します。 正常終了後、結果は以上の値をターゲットLSNに適用します。 このモードはリカバリ中にのみ使用できます。

  • <literal>standby_write</literal>: Wait for the WAL containing the LSN to be written to disk on a standby server, but not yet necessarily flushed. This is faster than <literal>standby_flush</literal> but provides weaker durability guarantees since the data may still be in operating system buffers. This is satisfied by WAL already present on the standby from a base backup, archive restore, or prior streaming, as well as WAL newly received from the primary. This mode can only be used during recovery. 《機械翻訳》standby_write:LSNを含むWALがディスク上のスタンバイサーバに書き込まれるまで待機しますが、まだフラッシュされる必要はありません。 これはstandby_flushより高速ですが、データがオペレーティングシステムバッファ内に残っている可能性があるため、耐久性の保証は弱くなります。 これは、ベースバックアップ、アーカイブリストア、または以前のストリーミングからスタンバイにすでに存在するWALと、プライマリから新たに受信したWALによって満たされます。 このモードはリカバリ中にのみ使用できます。

  • <literal>standby_flush</literal>: Wait for the WAL containing the LSN to be flushed to disk on a standby server. This provides a durability guarantee without waiting for the WAL to be applied. This is satisfied by WAL already present on the standby from a base backup, archive restore, or prior streaming, as well as WAL newly received from the primary. This mode can only be used during recovery. 《機械翻訳》standby_flush:LSNを含むWALがディスクのスタンバイサーバにフラッシュされるまで待機します。 これにより、WALが適用されるのを待たずに永続性が保証されます。 これは、ベースバックアップ、アーカイブリストア、または以前のストリーミングからスタンバイにすでに存在するWALと、プライマリから新たに受信したWALによって満たされます。 このモードはリカバリの間だけ使用できます。

  • <literal>primary_flush</literal>: Wait for the WAL containing the LSN to be flushed to disk on a primary server. After successful completion, <function>pg_current_wal_flush_lsn()</function> will return a value greater than or equal to the target LSN. This mode can only be used on a primary server (not during recovery). 《機械翻訳》primary_flush:LSNを含むWALがプライマリサーバでディスクにフラッシュされるのを待機します。 正常終了後、pg_current_wal_flush_lsn()結果は以上の値をターゲットLSNにします。 このモードはプライマリサーバでのみ使用できます（リカバリ中は使用できません）。

TIMEOUT 'timeout'

When specified and <parameter>timeout</parameter> is greater than zero, the command waits until <parameter>lsn</parameter> is reached or the specified <parameter>timeout</parameter> has elapsed. A value of zero (the default) means the command waits indefinitely. 《機械翻訳》指定したときにtimeoutがより大きいゼロの場合、コマンドはlsnに達するか、指定したtimeoutが経過するまで待機します。 値がゼロ（デフォルト）の場合、コマンドは無期限に待機します。

The <parameter>timeout</parameter> is an amount of time in milliseconds. It may also be specified as a string containing the numerical value followed by a time unit (see <xref linkend="config-setting-names-values"/>). The maximum value is <literal>2147483647 ms</literal>. 《機械翻訳》タイムアウトは、ミリ秒単位の時間です。 数値を含む文字列の後に時間ユニットが続くように指定することもできます（19.1.1を参照）。 最大値は2147483647 msです。

Fractional values are rounded to the nearest millisecond. Note that a <parameter>timeout</parameter> of half a millisecond or less therefore rounds down to zero, which means waiting indefinitely. 《機械翻訳》小数値は、最も近いミリ秒に丸められます。 そのノートtimeoutミリ秒の半分以下は、ダウンをゼロに丸めるため、無期限に待機することになります。

NO_THROW

Specify to not throw an error in the case of timeout or running on the primary. In this case the result status can be obtained from the return value. 《機械翻訳》タイムアウトのケースにエラーを投げない、またはプライマリを走行しないように指定します。 このケースでは、結果のステータスを戻り値から取得できます。

Use this option when <literal>timeout</literal> or <literal>not in recovery</literal> is an expected result that the application intends to handle, for example by retrying the wait, reporting replication delay, or choosing another server for a subsequent operation. The command then returns the result as a status, which the application must check before assuming that the target <acronym>LSN</acronym> was reached. Omit the option when the application must not proceed unless the target <acronym>LSN</acronym> is reached, so that an unsuccessful wait stops normal execution with an error. 《機械翻訳》このオプションは、timeoutまたはnot in recoveryが予期される結果である場合に使用します。 アプリケーションは、待機の再試行、ハンドル遅延のレポート、または後続の例に別のサーバを選択することによって、レプリケーションに対してオペレーションを実行しようとします。 コマンドは結果をステータスとして戻します。 このアプリケーションは、ターゲットLSNに到達したと仮定して、前をチェックする必要があります。 ターゲットLSNに到達しないかぎりアプリケーションを続行する必要がない場合は、オプションを省略します。 これにより、失敗した待機によってエラーによる通常の実行が停止されます。

Returning a status also leaves an explicit transaction usable; without this option, the corresponding error requires rolling back the transaction, or rolling back to a savepoint, before further commands can be issued. 《機械翻訳》ステータスを返すと、明示的なトランザクションも使用可能になります。 このオプションを使用しない場合、対応するエラーはトランザクションをロールバックするか、セーブポイント、前にロールバックする必要があります。 さらにコマンドを発行できます。

This option changes only how <literal>timeout</literal> and <literal>not in recovery</literal> are reported. Other errors are still raised. That covers invalid input, such as a malformed <acronym>LSN</acronym> or an unrecognized option value, and every condition that is checked before the wait begins, such as requesting <literal>primary_flush</literal> during recovery or holding a lock while waiting for a standby <acronym>LSN</acronym>. The option also does not limit the duration of the wait; specify <literal>TIMEOUT</literal> for that purpose. 《機械翻訳》このオプションで変更されるのは、timeoutおよびnot in recoveryの報告方法のみです。 その他のエラーも引き続き発生します。 これには、不正な形式LSNや認識されないオプション値などの無効な入力、およびprimary_flush前中のリクエストや、リカバリLSNを待機している間ロックを保留するなど、待機の開始前にチェックされるすべての状態が含まれます。 このオプションでは、待機時間も制限されません。 TIMEOUTそのために指定します。 スタンバイ

注釈

<title>Notes</title>

<command>WAIT</command> must be executed as a top-level command. It cannot be executed from a function, procedure, or <command>DO</command> block. It also cannot be executed while the current transaction holds a snapshot. <command>WAIT</command> itself acquires none, so it can run before the first snapshot-taking statement of a <literal>REPEATABLE READ</literal> or <literal>SERIALIZABLE</literal> transaction, but not after it, and not while a cursor or an exported snapshot holds one at any isolation level. A snapshot held here could delay replay, which <literal>standby_replay</literal> waits for and which other standby modes can end up waiting for too. That is also why <command>WAIT</command> is a command rather than a function or a procedure, which execute with one held. 《機械翻訳》WAITは、トップ-レベルコマンドとして実行する必要があります。 関数、プロシージャまたはDOブロックからは実行できません。 また、現在トランザクションがsnapshotを保持している間も実行できません。 WAIT自分自身は何も取得しないため、最初のsnapshotを取得するステートメントREPEATABLE READまたはSERIALIZABLEトランザクションを前で実行できますが、その後は実行できません。 また、カーソルまたはエクスポートされたsnapshotがいずれかの隔離レベルで1つを保持している間は実行できません。 ここに保持されているsnapshotは遅延リプレイであり、standby_replay待機し、他のスタンバイモードも待機することができます。 これもまた、WAITは関数やプロシージャではなくコマンドであり、実行は1つ保持されています。

While recovery is in progress, a wait in <literal>standby_replay</literal> (the default), <literal>standby_write</literal>, or <literal>standby_flush</literal> mode is rejected when the session already holds a lock and the target <parameter>lsn</parameter> has not been reached yet. Such a lock can make the startup process wait for this session, either directly or through another session, while this session waits for the startup process to advance recovery. That cycle involves no lock wait on this side, so deadlock detection does not see it and nothing breaks it. A wait whose target has already been reached returns immediately and is therefore always allowed. 《機械翻訳》リカバリが進行中の間、デフォルトがすでにモードを保持しており、セッションがlsnまだ到達していない場合、standby_replay（ロック）、standby_writeまたはstandby_flushターゲットは拒否されます。 このようなロックは、makeスタートアッププロセスが直接または別のセッションを介してこのセッションを待つことができ、一方、このセッションはスタートアッププロセスがリカバリを前進させるのを待つことができます。 そのサイクルにはこちら側のロック待機が含まれないため、デッドロック検出はそれを認識せず、何もそれを中断しません。 ターゲットがすでに到達している待機はすぐに戻るため、常に許可されます。

Issue <command>WAIT FOR</command> outside a transaction block, or as the first statement of one, before running anything that takes locks. That is also the natural order for the read-your-writes pattern shown in the examples below: wait for the target <parameter>lsn</parameter> first, then run the queries that have to see it. Note that a lock taken by an earlier statement is still held at <literal>READ COMMITTED</literal>, even though its snapshot is gone, so a wait placed after such a statement is rejected even when the isolation level permits it. 《機械翻訳》トランザクションブロック外でWAIT FORを発行するか、ステートメントの最初の前として、ロックを取得するものを実行するオーダーを発行します。 これは、次の例に示すread-your-writesパターンの自然なターゲットでもあります。 最初にロックlsnを待機し、それを参照する必要のある問い合わせを実行します。 前のステートメントによって取得されたがまだ保持されているノートREAD COMMITTED snapshotがなくなっても、このようなステートメントの後に配置された待機は、隔離レベルが許可した場合でも拒否されます。

The restriction covers <literal>standby_write</literal> and <literal>standby_flush</literal> as well, even though streaming replication can advance those positions without the startup process. Both positions are at least the replay position, so without an active walreceiver replay can be their only source of progress. If a held lock blocks replay, the session waits for replay to advance while replay waits for the session to release the lock. Under streaming replication the positions advance independently only while WAL keeps arriving. If reception stops before the target is reached, a blocked startup process cannot restart the walreceiver. It also cannot replay newer checkpoint records needed to advance restartpoints and recycle WAL, so <filename>pg_wal</filename> can fill up and reception can stop before the target is reached. The restriction therefore also applies when streaming is active at the start of the wait. 《機械翻訳》制限はstandby_writeおよびstandby_flush同様に、ストリーミングレプリケーションはスタートアップ位置なしでこれらのプロセスを進めることができますが。 どちらの位置も少なくともリプレイの位置にあるため、アクティブwalreceiverがなければ、リプレイは唯一の進歩のソースになる可能性があります。 保持されたロックがリプレイをブロックした場合、セッションはリプレイが進むのを待ち、リプレイはセッションからリリースロックまでを待ちます。 ストリーミングレプリケーションの下では、位置はWALが到着し続ける間にのみ独立して進みます。 受信が前を停止した場合、ターゲットに到達した場合、ブロックされたスタートアッププロセスはリスタートのwalreceiverになることはできません。 また、リプレイを進めてWALをリサイクルするために必要な新しいチェックポイントレコードをすることもできないため、pg_walターゲットが到達する前に満杯になり、受信が停止する可能性があります。 したがって、がアクティブである場合にも、ウェイトのプロビジョニングに適用されます。 リスタートポイントスタート前制限ストリーミング

<command>WAIT</command> waits until the specified <parameter>lsn</parameter> is reached according to the specified <parameter>mode</parameter>. The <literal>standby_replay</literal> mode waits for the LSN to be replayed (applied to the database), which is useful to achieve read-your-writes consistency while using an async replica for reads and the primary for writes, provided that the target <acronym>LSN</acronym> is at or after the end of the relevant write transaction's <literal>COMMIT</literal> record on the primary. The <literal>standby_flush</literal> mode waits for the WAL to be flushed to durable storage on the replica, or to have already been replayed from WAL present on the standby. The <literal>standby_write</literal> mode waits for the WAL to be written to the operating system, or to have already been replayed, which is faster than flush for newly received WAL but provides weaker durability guarantees. The <literal>primary_flush</literal> mode waits for WAL to be flushed on a primary server. In all cases, the <acronym>LSN</acronym> of the last modification should be stored on the client application side or the connection pooler side. 《機械翻訳》WAITは、指定されたモードに従って、指定されたlsnに達するまで待機します。 standby_replayモードは、LSNが再生される（データベースに適用される）のを待機します。 これは、読み取りに非同期一貫性を使用し、書き込みにレプリカを使用しながら、read-your-writesプライマリを実現するのに便利です。 ただし、ターゲットLSNがプライマリ上の関連する書き込みトランザクションCOMMITレコードの末尾または末尾以降にある必要があります。 standby_flushモードは、WALがレプリカ上の永続ストレージにフラッシュされるか、スタンバイ上のWALからすでに再生されているのを待機します。 standby_writeモードは、WALがオペレーティングシステムに書き込まれるか、すでに再生されているのを待機します。 これは、新たに受信したWALに対してフラッシュよりも高速ですが、永続性の保証は弱くなります。 primary_flushモードは、プライマリサーバ上でWALがフラッシュされるのを待機します。 いずれの場合も、最後の変更のLSNはクライアントアプリケーション側またはコネクションプーラ側に格納する必要があります。

The standby modes (<literal>standby_replay</literal>, <literal>standby_write</literal>, <literal>standby_flush</literal>) can only be used during recovery, and <literal>primary_flush</literal> can only be used on a primary server. Using the wrong mode for the current server state will result in an error. If a standby is promoted while waiting with a standby mode, the command will return <literal>not in recovery</literal> (or throw an error if <literal>NO_THROW</literal> is not specified). Promotion creates a new timeline, and the LSN being waited for may refer to WAL from the old timeline. 《機械翻訳》スタンバイモードstandby_replay,standby_write,standby_flushはリカバリ中のみ使用でき、primary_flushはプライマリサーバ上でのみ使用できます。 間違いモードを現在サーバ状態に使用すると、エラーになります。 スタンバイがスタンバイモードと待機中にプロモートされた場合、コマンドは結果not in recoveryまたは、NO_THROW指定されていない場合はエラーをスローします。 プロモートにより、新しいタイムラインが作成され、待機中のLSNは古いタイムラインからのWALを参照できます。

<command>WAIT</command> compares only the numeric <acronym>LSN</acronym>; it has no notion of which timeline a WAL record belongs to. This matters when a standby continues recovery across an upstream timeline switch &mdash; for example, a cascading standby whose upstream gets promoted. In that case <command>WAIT</command> will return <literal>success</literal> as soon as the position used by the selected wait mode reaches or passes the numeric <acronym>LSN</acronym>, regardless of which timeline that <acronym>LSN</acronym> belongs to. Applications that need to confirm the target refers to the expected timeline must validate the timeline themselves. 《機械翻訳》WAITは数値LSNのみを比較します。 WALタイムラインがどのレコードに属しているかという概念はありません。 これは、スタンバイがアップストリームタイムラインスイッチを横切ってリカバリを継続する場合に重要です。 例の場合、アップストリームがプロモートされるカスケードスタンバイです。 そのケースでは、LSNがどのタイムラインに属しているかに関係なく、WAITは結果success選択された待機モードによって使用される位置が数値LSNに到達またはそれを超えるとすぐにします。 ターゲットが予想されるタイムラインを参照していることを確認する必要があるアプリケーションは、タイムライン自体を検証する必要があります。

On a standby server, <command>WAIT</command> sessions may be interrupted by recovery conflicts. Some recovery conflicts are unavoidable: for example, replaying a tablespace drop resolves conflicts by terminating all backends, regardless of what they are doing. Applications using <command>WAIT</command> on a standby should be prepared to handle such interruptions, for example by retrying the command or falling back to an alternative mechanism. 《機械翻訳》スタンバイサーバでは、WAITセッションはリカバリの競合によって中断される場合があります。 一部のリカバリの競合は避けられません。 例の場合、テーブルスペースドロップをリプレイすると、バックエンドが何をしているかに関係なく、すべてのバックエンドを終了することによって競合が解決されます。 スタンバイでWAITを使用するアプリケーションは、このような中断をハンドルに対してプリペアドする必要があります。 例の場合は、コマンドを再試行するか、別のメカニズムにフォールバックします。

For example, an application could update the <literal>movie</literal> table and get an <acronym>lsn</acronym> that is at or after the end of the relevant write transaction's <literal>COMMIT</literal> record. In the default autocommit mode shown here, the <command>UPDATE</command> commits before the subsequent <command>SELECT</command>. This example uses <function>pg_current_wal_insert_lsn</function> on primary server to get the <acronym>lsn</acronym> given that <varname>synchronous_commit</varname> could be set to <literal>off</literal>. 《機械翻訳》WAITコマンドを使用してpg_lsn値を待つことができます。 例の場合、アプリケーションはmovieテーブルを更新し、関連する書込みトランザクションのコミットレコードの最後または最後以降にあるlsnを取得できます。 ここに示すデフォルト自動コミットモードでは、UPDATEがその後のSELECTを前にコミットします。 この例では、synchronous_commitがoffに設定されている可能性があるため、pg_current_wal_insert_lsn onプライマリサーバを使用してlsnを取得します。

Then an application could run <command>WAIT</command> with the <parameter>lsn</parameter> obtained from the primary after the commit. After that, the changes made on the primary should be guaranteed to be visible on the replica. 《機械翻訳》次に、アプリケーションをWAITコミットの後にプライマリから取得したlsnを使用して実行できます。 その後、プライマリで行われた変更は、レプリカの可視であることが保証される必要があります。 

postgres=# WAIT FOR LSN '0/0306EE20';
 status
---------
 success
(1 row)
postgres=# SELECT * FROM movie WHERE genre = 'Drama';
 genre
-------
(0 rows)

Wait for flush (data durable on replica): 《機械翻訳》フラッシュを待つ（レプリカのデータ）:。 

postgres=# WAIT FOR LSN '0/0306EE20' WITH (MODE 'standby_flush');

(1 row)

Wait for write with timeout: 《機械翻訳》タイムアウト:での書き込みを待ちます。 

postgres=# WAIT FOR LSN '0/0306EE20' WITH (MODE 'standby_write', TIMEOUT '100ms', NO_THROW);

Wait for flush on primary: 《機械翻訳》プライマリでフラッシュを待ちなさい。 

postgres=# WAIT FOR LSN '0/0306EE20' WITH (MODE 'primary_flush');

---------
 success
(1 row)

If the target LSN is not reached before the timeout, an error is thrown: 《機械翻訳》ターゲットLSNが前タイムアウトに到達しない場合、エラーがスローされます。 

postgres=# WAIT FOR LSN '0/0306EE20' WITH (TIMEOUT '0.1s');
ERROR:  timed out while waiting for target LSN 0/0306EE20 to be replayed; current standby_replay LSN 0/0306EA60

The same example uses <command>WAIT</command> with the <parameter>NO_THROW</parameter> option: 《機械翻訳》同じ例でWAITとNO_THROWオプション:. 

postgres=# WAIT FOR LSN '0/0306EE20' WITH (TIMEOUT '100ms', NO_THROW);
 status
---------
 timeout
