E.1.1. 概要 #

<title>Overview</title>

<productname>PostgreSQL</productname> 19 contains many new features and enhancements, including: PostgreSQL 19には、以下をはじめとする多数の新機能と拡張が含まれています。

  • New <xref linkend="sql-repack"/> command that reclaims disk space and reorganizes table contents, which can improve query performance. <command>REPACK (CONCURRENTLY)</command> allows repacking without blocking reads and writes to the table. 新しいREPACKコマンドは、ディスクスペースを再利用し、テーブルの内容を再編成します。 これにより、問い合わせのパフォーマンスが向上する可能性があります。 REPACK (CONCURRENTLY)を使用すると、テーブルへの読み取りおよび書き込みをブロックせずに再編成できます。

  • <xref linkend="pgplanadvice"/> extension for controlling query planner decisions and <xref linkend="pgstashadvice"/> extension that applies plan advice automatically based on the query. 問い合わせプランナの決定を制御するpg_plan_advice拡張機能と、問い合わせアドバイスを自動的に適用するpg_stash_advice拡張機能が追加されました。

  • Better performance in many areas, including automatic scaling of the number of I/O worker processes, quicker foreign-key checks, and further planning and execution optimizations. 多くの領域でパフォーマンスが改善されました。 たとえば、入出力ワーカープロセス数の自動スケーリング、外部キーチェックの高速化、計画および実行のさらなる最適化などです。

  • Logical replication can now be enabled without a server restart when <xref linkend="guc-wal-level"/> is set to <literal>replica</literal>. wal_levelがreplicaに設定されている場合、論理レプリケーションリスタートなしでサーバを有効にできるようになりました。

  • Logical replication of <link linkend="logical-replication-sequences">sequence values</link>. シーケンス値の論理レプリケーションが可能になりました。

  • Support for <quote>read-your-writes</quote> consistency on standbys via the new <xref linkend="sql-wait"/> command. 「read-your-writes」一貫性のサポートは、新しいWAITコマンドを経由してスタンバイ状態で利用可能になりました。

  • <link linkend="guc-autovacuum-max-parallel-workers">Parallel autovacuum of table indexes</link> and <link linkend="autovacuum-priority">autovacuum prioritization</link> through a new scoring system. テーブルインデックスのパラレル自動バキュームと自動バキュームの優先順位付けは、新しいスコアリングシステムを通じて行われるようになりました。

The above items and other new features of <productname>PostgreSQL</productname> 19 are explained in more detail in the sections below. PostgreSQL 19の上記の項目とその他の新機能は次節でより詳しく説明されます。

E.1.2. バージョン19への移行 #

<title>Migration to Version 19</title>

A dump/restore using <xref linkend="app-pg-dumpall"/> or use of <xref linkend="pgupgrade"/> or logical replication is required for those wishing to migrate data from any previous release. See <xref linkend="upgrading"/> for general information on migrating to new major releases. 以前のリリースからデータを移行したい時は、どのリリースについても、pg_dumpallを利用したダンプとリストア、あるいはpg_upgradeや論理レプリケーションの使用が必要です。 新たなメジャーバージョンへの移行に関する一般的な情報については18.6を参照してください。
