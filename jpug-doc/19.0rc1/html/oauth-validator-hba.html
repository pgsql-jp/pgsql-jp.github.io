50.4. Custom HBA Options #

Like other preloaded libraries, validator modules may define <link linkend="runtime-config-custom">custom GUC parameters</link> for user configuration in <filename>postgresql.conf</filename>. However, it may be desirable to configure behavior at a more granular level (say, for a particular issuer or a group of users) instead of globally. 《機械翻訳》他のプリロードされたライブラリと同様に、バリデータモジュールは、ユーザ設定のためにカスタムGUCパラメータを定義することができるpostgresql.conf。 しかし、グローバルに、より細かいレベル（例えば、特定の発行者またはユーザのグループ）で動作を設定することが望ましい場合がある。 代わり

Beginning in <productname>PostgreSQL</productname> 19, validator implementations may define custom options for use inside <filename>pg_hba.conf</filename>. These options are then <link linkend="auth-oauth-validator-option">made available</link> to the user as <literal>validator.<replaceable>option</replaceable></literal>. The API for registering and retrieving custom options is described below. 《機械翻訳》PostgreSQL19から、バリデータ実装は内部で使用するためにカスタムオプションを定義することができますpg_hba.conf。 これらのオプションは、validator.optionとしてそのユーザに対して利用可能にされる。 APIを登録および取得するためのカスタムオプションは、以下で説明されます。

50.4.1. Options API #

Modules register custom HBA option names during the <function>startup_cb</function> callback, using <function>RegisterOAuthHBAOptions()</function>: 《機械翻訳》モジュール登録カスタムHBAオプション名をstartup_cbコールバック、RegisterOAuthHBAOptions():. 

/*
 * Register a list of custom option names for use in pg_hba.conf. For each name
 * "foo" registered here, that option will be provided as "validator.foo" in
 * the HBA.
 *
 * Valid option names consist of alphanumeric ASCII, underscore (_), and hyphen
 * (-). Invalid option names will be ignored with a WARNING logged at
 * connection time.
 *
 * This function may only be called during the startup_cb callback. Multiple
 * calls are permitted, which will append to the existing list of registered
 * options; options cannot be unregistered.
 *
 * Parameters:
 *
 * - state: the state pointer passed to the startup_cb callback
 * - num:   the number of options in the opts array
 * - opts:  an array of null-terminated option names to register
 *
 * The list of option names is copied internally, and the opts array is not
 * required to remain valid after the call.
 */
void RegisterOAuthHBAOptions(ValidatorModuleState *state, int num,
                             const char *opts[]);

Each option's value, if set, may be later retrieved using <function>GetOAuthHBAOption()</function>: 《機械翻訳》各オプションの値は、設定された場合、後でGetOAuthHBAOption():を使用して取得できます。 

/*
 * Retrieve the string value of an HBA option which was registered via
 * RegisterOAuthHBAOptions(). Usable only during validate_cb or shutdown_cb.
 *
 * If the user has set the corresponding option in pg_hba.conf, this function
 * returns that value as a null-terminated string, which must not be modified
 * or freed. NULL is returned instead if the user has not set this option, if
 * the option name was not registered, or if this function is incorrectly called
 * during the startup_cb.
 *
 * Parameters:
 *
 * - state:   the state pointer passed to the validate_cb/shutdown_cb callback
 * - optname: the name of the option to retrieve
 */
const char *GetOAuthHBAOption(const ValidatorModuleState *state,
                              const char *optname);

See <xref linkend="oauth-validator-hba-example-usage"/> for sample usage. 《機械翻訳》サンプル利用については50.4.3を見てください。

50.4.2. 制限事項 #

<title>Limitations</title>

  • Option names are limited to ASCII alphanumeric characters, underscores (<literal>_</literal>), and hyphens (<literal>-</literal>). 《機械翻訳》オプション名には、ASCII英数字、アンダースコア_、およびハイフン(-)しか使用できません。

  • Option values are always freeform strings (in contrast to custom GUCs, which support numerics, booleans, and enums). 《機械翻訳》オプションの値は常に自由形式の文字列です（カスタムの数値、ブール値、列挙型であるサポートのGUCsとは対照的です）。

  • Option names and values cannot be checked by the server during a reload of the configuration. Any unregistered options in pg_hba.conf will instead result in connection failures. It is the responsibility of each module to document and verify the syntax of option values as needed. [18]

50.4.3. 使用例 #

<title>Example Usage</title>

For a hypothetical module, the options <literal>foo</literal> and <literal>bar</literal> could be registered as follows: 《機械翻訳》仮定のモジュールの場合、オプションfooおよびbarは、次のように登録できます。 

static void
validator_startup(ValidatorModuleState *state)
{
    static const char *opts[] = {
        "foo",      /* description of access privileges */
        "bar",      /* magic URL for additional administrator powers */
    };

    RegisterOAuthHBAOptions(state, lengthof(opts), opts);

    /* ...other setup... */
}

The following sample entries in <filename>pg_hba.conf</filename> can then make use of these options: 《機械翻訳》の次のサンプルエントリpg_hba.conf makeはこれらのオプションを使用できます。 

# TYPE   DATABASE   USER   ADDRESS    METHOD
hostssl  postgres   admin  0.0.0.0/0  oauth issuer=https://admin.example.com \
                                            scope="pg-admin openid email" \
                                            map=oauth-email \
                                            validator.foo="admin access" \
                                            validator.bar=https://magic.example.com

hostssl  postgres   all    0.0.0.0/0  oauth issuer=https://www.example.com \
                                            scope="pg-user openid email" \
                                            map=oauth-email \
                                            validator.foo="user access"

The module can retrieve the option settings from the HBA during validation: 《機械翻訳》モジュールは、バリデーション中にHBAからオプション設定を取得できます。 

static bool
validate_token(const ValidatorModuleState *state,
               const char *token, const char *role,
               ValidatorModuleResult *res)
{
    const char *foo = GetOAuthHBAOption(state, "foo"); /* "admin access" or "user access" */
    const char *bar = GetOAuthHBAOption(state, "bar"); /* "https://magic.example.com" or NULL */

    if (bar && !is_valid_url(bar))
    {
        res->error_detail = psprintf("validator.bar (\"%s\") is not a valid URL.", bar);
        return false;
    }

    /* proceed to validate token */
}

When multiple validators are in use, their registered option lists remain independent: 《機械翻訳》マルチプルバリデータが使用されている場合、登録されたオプションリストは独立したままになります。 

in postgresql.conf:
oauth_validator_libraries = 'example_org, my_validator'

in pg_hba.conf:
# TYPE   DATABASE   USER   ADDRESS    METHOD
hostssl  postgres   admin  0.0.0.0/0  oauth issuer=https://admin.example.com \
                                            scope="pg-admin openid email" \
                                            map=oauth-email \
                                            validator=my_validator \
                                            validator.foo="admin access" \
                                            validator.bar=https://magic.example.com

hostssl  postgres   all    0.0.0.0/0  oauth issuer=https://www.example.org \
                                            scope="pg-user openid profile" \
                                            validator=example_org \
                                            delegate_ident_mapping=1 \
                                            validator.magic=on \
                                            validator.more_magic=off


[18] If a module finds an invalid option value during <function>validate_cb</function>, it's recommended to <link linkend="oauth-validator-callback-validate">signal an internal error</link> by setting <structfield>result->error_detail</structfield> to a description of the problem and returning <literal>false</literal>. 《機械翻訳》validate_cbの最中にモジュールが無効なオプション値を見つけた場合には、result->error_detailに問題の説明を設定し、falseを返すことによって、内部のエラーを通知することをお勧めします。
