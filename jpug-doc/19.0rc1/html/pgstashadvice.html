F.33. pg_stash_advice — store and automatically apply plan advice #

The <filename>pg_stash_advice</filename> extension allows you to stash <link linkend="pgplanadvice">plan advice</link> strings in dynamic shared memory where they can be automatically applied. An <literal>advice stash</literal> is a mapping from <link linkend="guc-compute-query-id">query identifiers</link> to plan advice strings. Whenever a session is asked to plan a query whose query ID appears in the relevant advice stash, the plan advice string is automatically applied to guide planning. Note that advice stashes are stored in dynamically allocated shared memory. This means that it is important to be mindful of memory consumption when deciding how much plan advice to stash. Optionally, advice stashes and their contents can automatically be persisted to disk and reloaded from disk; see <literal>pg_stash_advice.persist</literal>, below. 《機械翻訳》pg_stash_adviceextensionを使用すると、プランアドバイス文字列を動的共有メモリに隠して、自動的に適用できます。 advice stashは問い合わせ識別子からプランアドバイス文字列までのマッピングです。 セッションがプラン問い合わせに要求され、その問い合わせIDが関連するアドバイス隠しに表示されるたびに、プランアドバイス文字列がガイドplanning. ノートに自動的に適用され、アドバイス隠しが動的に割り当てられた共有メモリに格納されます。 これは、プランアドバイスの量を決定する際に、メモリの消費に注意することが重要であることを意味します。 オプションで、アドバイス隠しとその内容を自動的にディスクに保持し、ディスクから再ロードすることができます。 下記のpg_stash_advice.persistを参照してください。

In order to use this module, you will need to execute <literal>CREATE EXTENSION pg_stash_advice</literal> in at least one database, so that you have access to the SQL functions to manage advice stashes. You will also need the <literal>pg_stash_advice</literal> module to be loaded in all sessions where you want this module to automatically apply advice. It will usually be best to do this by adding <literal>pg_stash_advice</literal> to <xref linkend="guc-shared-preload-libraries"/> and restarting the server. 《機械翻訳》オーダーでこのモジュールを使用するには、実行CREATE EXTENSION pg_stash_advice少なくとも1つのデータベースで、アクセスからSQLへの機能を使用してアドバイスの隠し場所を管理する必要があります。 また、このモジュールでアドバイスを自動的に適用するすべてのセッションでpg_stash_adviceモジュールをロードする必要があります。 通常はベストで、shared_preload_librariesにpg_stash_adviceを追加し、サーバを再起動します。

Once you have met the above criteria, you can create advice stashes using the <literal>pg_create_advice_stash</literal> function described below and set the plan advice for a given query ID in a given stash using the <literal>pg_set_stashed_advice</literal> function. Then, you need only configure <literal>pg_stash_advice.stash_name</literal> to point to the chosen advice stash name. For some use cases, rather than setting this on a system-wide basis, you may find it helpful to use <literal>ALTER DATABASE ... SET</literal> or <literal>ALTER ROLE ... SET</literal> to configure values that will apply only to a database or only to a certain role. Likewise, it may sometimes be better to set the stash name in a particular session using <literal>SET</literal>. 《機械翻訳》前述の基準を満たした後は、pg_create_advice_stash後述のアドバイスを使用して関数の隠し場所を作成し、pg_set_stashed_adviceプランを使用して、特定の隠し場所の特定の問い合わせIDに対して関数アドバイスを設定できます。 その後は、pg_stash_advice.stash_name選択したアドバイスの隠し場所名前にポイントするように構成するだけで済みます。 一部のユースケースでは、システム全体にこの値を設定するよりも、データベースまたは特定のロールのみに適用される値を構成するためにALTER DATABASE ... SETまたはALTER ROLE ... SETを使用することをお薦めします。 同様に、SETを使用して特定のセッションに隠し場所名前を設定する方がよい場合もあります。

Because <literal>pg_stash_advice</literal> works on the basis of query identifiers, you will need to determine the query identifier for each query whose plan you wish to control. You will also need to determine the advice string that you wish to store for each query. One way to do this is to use <literal>EXPLAIN</literal>: the <literal>VERBOSE</literal> option will show the query ID, and the <literal>PLAN_ADVICE</literal> option will show plan advice. Query identifiers can also be obtained through tools such as <xref linkend="pgstatstatements" /> or <xref linkend="monitoring-pg-stat-activity-view" />, but these tools will not provide plan advice strings. Note that <xref linkend="guc-compute-query-id" /> must be enabled for query identifiers to be computed; if set to <literal>auto</literal>, loading <literal>pg_stash_advice</literal> will enable it automatically. 《機械翻訳》pg_stash_adviceは問い合わせ識別子に基づいて動作するため、問い合わせをコントロールにしたい問い合わせごとに、プラン識別子を決定する必要があります。 また、各問い合わせに対して保存したいアドバイス文字列を決定する必要もあります。 これを行う1つの方法は、EXPLAIN:VERBOSEオプションは問い合わせIDを表示し、PLAN_ADVICEオプションはプランアドバイスを表示します。 問い合わせ識別子はpg_stat_statementsや27.2.3などのツールを使用して取得することもできますが、これらのツールはプランアドバイス文字列を提供しません。 ノート問い合わせ識別子を計算するには、このcompute_query_idが有効になっている必要があります。 autoに設定されている場合、ロード時にpg_stash_adviceは自動的に有効になります。

Generally, the fact that the planner is able to change query plans as the underlying distribution of data changes is a feature, not a bug. Moreover, applying plan advice can have a noticeable performance cost even when it does not result in a change to the query plan. Therefore, it is a good idea to use this feature only when and to the extent needed. Plan advice strings can be trimmed down to mention only those aspects of the plan that need to be controlled, and used only for queries where there is believed to be a significant risk of planner error. 《機械翻訳》一般的に、プランナの基礎となるディストリビューションが変更されたときにデータが問い合わせ計画を変更できるのは、機能であってバグではありません。 さらに、プランアドバイスを適用すると、問い合わせプランへの変更を伴わない場合でも、顕著なパフォーマンスコストが発生する可能性があります。 したがって、この機能は、必要なときに必要なエクステントにのみ使用するのが良いアイディアです。 プランアドバイス文字列はダウンをトリムして、制御が必要なプランの側面のみを言及し、プランナエラーのかなりのリスクがあると考えられる問い合わせにのみ使用できます。

Note that <literal>pg_stash_advice</literal> currently lacks a sophisticated security model. Only the superuser, or a user to whom the superuser has granted <literal>EXECUTE</literal> permission on the relevant functions, may create advice stashes or alter their contents, but any user may set <literal>pg_stash_advice.stash_name</literal> for their session, and this may reveal the contents of any advice stash with that name. Users should assume that information embedded in stashed advice strings may become visible to non-privileged users. 《機械翻訳》ノートpg_stash_advice現在、高度なセキュリティモデルがありません。 スーパーユーザまたはユーザが付与したスーパーユーザEXECUTE関連する機能に関するパーミッションのみが、アドバイスの隠し場所を作成したり、その内容を変更したりできますが、ユーザはpg_stash_advice.stash_nameそのセッションに対して設定することができ、これにより、その名前とともに隠されているアドバイスの内容が明らかになる可能性があります。 ユーザは、隠されたアドバイス文字列内の情報埋め込みが、特権のないユーザには可視になる可能性があると想定する必要があります。

F.33.1. Functions #

pg_create_advice_stash(stash_name text) returns void

Creates a new, empty advice stash with the given name. 《機械翻訳》指定されたアドバイスで、新しい空の名前の隠し場所を作成します。

pg_drop_advice_stash(stash_name text) returns void

Drops the named advice stash and all of its entries. 《機械翻訳》記名的アドバイスのstashとそのすべてのエントリを削除します。

pg_set_stashed_advice(stash_name text, query_id bigint, advice_string text) returns void

Stores an advice string in the named advice stash, associated with the given query identifier. If an entry for that query identifier already exists in the stash, it is replaced. If <parameter>advice_string</parameter> is <literal>NULL</literal>, any existing entry for that query identifier is removed. 《機械翻訳》指定したアドバイス文字列に関連付けられた記名的アドバイスのスタッシュに問い合わせ識別子を格納します。 その問い合わせ識別子のエントリがすでにスタッシュに存在する場合は、置き換えられます。 advice_stringがNULLの場合は、その問い合わせ識別子の既存のエントリが削除されます。

pg_get_advice_stashes() returns setof (stash_name text, num_entries bigint)

Returns one row for each advice stash, showing the stash name and the number of entries it contains. 《機械翻訳》行の各隠し場所に対して1つのアドバイスを返し、隠し場所の名前とその包含のエントリ数を表示します。

pg_get_advice_stash_contents(stash_name text) returns setof (stash_name text, query_id bigint, advice_string text)

Returns one row for each entry in the named advice stash. If <parameter>stash_name</parameter> is <literal>NULL</literal>, returns entries from all stashes. 《機械翻訳》行アドバイススタッシュ内のエントリごとに1つの記名的を戻します。 stash_nameがNULLの場合は、すべてのスタッシュからエントリが戻されます。

pg_start_stash_advice_worker() returns void

Starts the background worker, so that advice stash contents can be automatically persisted to disk. If this module is included in <xref linkend="guc-shared-preload-libraries"/> at startup time with <literal>pg_stash_advice.persist = true</literal>, the worker will be started automatically. When started manually, the worker will not load anything from disk, but it will still persist data to disk. You can then configure the server to start the worker automatically after the next restart, preserving any stashed advice you add now. 《機械翻訳》バックグラウンドワーカーを起動し、アドバイスのstashコンテンツを自動的にディスクに永続化できるようにします。 このモジュールがpg_stash_advice.persist = trueでスタートアップ時間にshared_preload_librariesに含まれている場合、ワーカーは自動的に起動されます。 手動で起動した場合、ワーカーはディスクから何もロードしませんが、データからディスクまでは存続します。 次のリスタートの後に、サーバからワーカーに自動的にスタートするように構成できます。 これにより、今追加したstashアドバイスが保持されます。

F.33.2. 設定パラメータ #

<title>Configuration Parameters</title>
pg_stash_advice.persist (boolean)

Controls whether the advice stashes and stash entries should be persisted to disk. This is on by default. If any stashes are persisted, a file named <literal>pg_stash_advice.tsv</literal> will be created in the data directory. Stashes are loaded and saved using a background worker process. This parameter can only be set at server start. 《機械翻訳》アドバイスのstashおよびstashエントリをディスクに保持するかどうかを制御します。 これはデフォルトによるものです。 stashが保持されている場合は、ファイルに記名的pg_stash_advice.tsvが作成されます。 stashはバックグラウンドワーカープロセスを使用してロードおよび保存されます。 このパラメータはサーバスタートでのみ設定できます。 データディレクトリ

pg_stash_advice.persist_interval (integer)

Specifies the interval, in seconds, between checks for changes that need to be written to <literal>pg_stash_advice.tsv</literal>. If set to zero, changes are only written when the server shuts down. The default value is <literal>30</literal>. This parameter can only be set in the <filename>postgresql.conf</filename> file or on the server command line. 《機械翻訳》書き込む必要がある変更をチェックする間隔pg_stash_advice.tsv秒を指定します。 ゼロに設定すると、サーバがダウンを閉鎖するときにのみ変更が書き込まれます。 デフォルト値は30です。 このパラメータは、postgresql.confファイルまたはサーバコマンドラインでのみ設定できます。 インターバル

pg_stash_advice.stash_name (string)

Specifies the name of the advice stash to consult during query planning. The default value is the empty string, which disables this module. 《機械翻訳》問い合わせの計画中に参照される名前の隠し場所のアドバイスを指定します。 デフォルト値は空の文字列で、このモジュールを無効にします。
